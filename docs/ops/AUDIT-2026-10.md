# Architecture audit, October 2026

Scope: reliability, security, performance, PostgreSQL/PostGIS, responsiveness, testing and
environment compatibility of the API, portal and apps. Run on the build environment against
**test databases only** (`cwm_test`, `cwm_e2e_test`, and `cwm_load_test` with 365,000 complaints and
1.6 M events for one ULB). There is no production or staging environment yet; nothing outside the
build environment was touched.

Outcome classes used below: PASS, PASS WITH WARNINGS, FAIL, NOT FULLY VERIFIED.

## Findings and fixes

| ID | Severity | Finding | Fix | Evidence |
|---|---|---|---|---|
| H1 | High | A 50,000-row Excel export took 10.2 s, blocked the API event loop for 8 s and grew memory by ~1.1 GB; no concurrency limit, no container memory limit. Two officers exporting at once could take the API down for everyone. | Streaming ExcelJS writer, yields every 500 rows; one export per user and two per process (429); compose memory limits. Cap (50,000) and columns unchanged. | Same 50,000 × 19 workload: 3.9 s, peak +83 MB, longest block 70 ms; file re-read and checked. `export-slots.spec`, `reports.e2e` slot test. |
| H2 | High | Sign-out revoked only the refresh token: a copied access token kept working for up to 15 minutes (live test: `/auth/me` and the inbox answered 200 after logout). | Access tokens carry the session id (`sid`); the guard rejects tokens of a revoked session in the query it already runs. Tokens from before the change get one 401 and are renewed by the apps' and portal's refresh-on-401. | `auth.e2e` (copied token dead, other device unaffected, pre-refresh token), `security/authentication` (no/unknown/foreign sid). 4 assertions failed before the fix. |
| H3 | High | Found by the failure drill. Redis down: a complaint action committed in the database but its HTTP request never answered (post-commit job enqueue on an unlimited-retry connection). Readiness hung > 30 s; shutdown hung until SIGKILL. | Enqueue gives up after 2 s (the command still runs once Redis returns; push delivery and video transcoding have sweeps); bounded readiness ping; bounded shutdown. | Drill: complaint action 201 in 2.0 s, ready 503 in 2.0 s, shutdown 5 ms. `security/redis-outage` (4 tests). |
| M1 | Medium | No statement, idle-in-transaction or connection-wait timeout: one stuck transaction holding the pool hung every request. | API 30 s / worker 5 min statements, 60 s idle transaction, 10 s connection wait (all `DB_*` configurable); scripts and migrations unlimited. Limits and outages answer 503 with a retry message. | Heaviest report measured at 2.5 s (366 days, statewide, 365k). `security/db-limits` (3/3 failed before), `all-exceptions.filter.spec`. |
| M2 | Medium | The duplicate search (metres via `::geography`) could not use the geometry index: full scan per lookup, 62 ms warm / 643 ms cold at 365k. | GiST index on the same `(location::geography)` expression, built `CONCURRENTLY`. No change to columns, SRID or query. | 9.6–11 ms after. Build 3.2 s on 365k with a concurrent write completing in 0.5 s. `migrations.e2e` (valid, used, reversible). |
| M3 | Medium | Ward uploads were not checked for overlap, and the GPS lookup had no ORDER BY: a point in two wards could route to either supervisor. | Refuse overlap > 100 m² with another active ward of the ULB (create, boundary change, re-activation; serialised per ULB); lookups order by ward id. `ST_Contains` semantics unchanged. | `masters.e2e` (3 of 5 new tests failed before; the determinism test cannot fail reliably on old code). `infra/sql/check-ward-overlaps.sql`: 0 overlaps in the load-test data. |
| M4 | Medium | The intermittent portal test "signing out ends the session" (about 1 in 25): the user menu was attached to `<body>` while its button sat in the sticky header; a scroll moved it, it snapped back between mouse-down and mouse-up, and the click hit nothing. **No logout request was sent.** This corrects the PR's earlier description ("cookies cleared yet dashboard shown"), which was not supported by evidence. | Menu opens on click and lives inside the header; failed sign-out says so; the test asserts the logout request. | Instrumented traces of 3 lost clicks; drift test (240 px before, 0 after); sign-out tests 100/100. |
| M5 | Medium | Found while fixing H2. A browser holding an unexpired token the API rejects (disabled account, password changed elsewhere, revoked session) looped between `/dashboard` and `/login` (`ERR_TOO_MANY_REDIRECTS`) for up to 15 minutes. | Layout hands over to `/bff/auth/session-ended`: one refresh attempt, otherwise cookies cleared and sign-in. API errors other than 401 show the error page instead of signing anyone out. | Playwright: loop reproduced before, sign-in page after; pre-binding token renewed silently. |
| L1 | Low | `new HttpException('text')` reached clients as a bare string; the apps could not show the media upload-limit messages. | Wrapped as `{ statusCode, message }` in the global filter. | `security/media` (failed before), filter unit test. |
| L2 | Low | Database down returned a bare 500. | 503 "temporarily unavailable", logged under `Dependencies`. | Drill: 503 in 13 ms, recovers without restart. |
| L3 | Low | CI ran twice per push to a branch with an open PR. | Push runs only on `main`; PRs and manual runs unchanged. | Workflow syntax checked; takes effect on the next push. |

Not changed (accepted for the pilot): request rate limits are per API process (account lockout is in
the database); portal refresh single-flight is per process (one portal replica or sticky sessions);
a GPS point exactly on a ward boundary falls back to manual ward choice (by design).

Re-checked and not an issue: inbox count and list on 365k complaints run in 47–95 ms once table
statistics are current (an earlier 1.35 s reading was stale statistics, so no index was added); spatial
columns are SRID 4326 with distances in metres via `::geography`; report windows are capped at 366 days
and exports at 50,000 rows; media uploads are size-, type-, signature- and malware-checked.

## Deploying these changes
- Migration `DuplicateSearchIndex1762000000000` builds an index concurrently (seconds at pilot scale; no
  write lock). If it is interrupted, re-running the migration drops the invalid leftover first.
- After deploy every signed-in user's next request renews its access token once (no sign-out).
- New optional settings: `DB_POOL_MAX`, `DB_STATEMENT_TIMEOUT_MS`, `DB_IDLE_IN_TRANSACTION_TIMEOUT_MS`,
  `DB_CONNECTION_TIMEOUT_MS`, `JOBS_REDIS_WAIT_MS` (defaults in `apps/api/.env.example`).
- Compose memory limits: API 1 GB (matches the soak-test alert threshold; the restart policy brings it
  back if exceeded), worker 2 GB (FFmpeg), portal 512 MB.
- Run `infra/sql/check-ward-overlaps.sql` after loading ward boundaries outside the portal.
